Connect to a channel

const agent = new AgentConnection();

agent.connect({
  channelName:     'my-room',
  channelPassword: 'secret123',
  agentName:       'player-1',
  apiKey:          'your-api-key'

var agent = new AgentConnection();

agent.connect(ConnectRequest.builder()
    .channelName("my-room")
    .channelPassword("secret123")
    .agentName("player-1")
    .apiKey("your-api-key")
    .build());
agent = AgentConnection()

agent.connect(
    channel_name="my-room",
    channel_password="secret123",
    agent_name="player-1",
    api_key="your-api-key",
)
AgentConnection agent;

ConnectRequest req;
req.channelName     = "my-room";
req.channelPassword = "secret123";
req.agentName       = "player-1";
req.apiKey          = "your-api-key";

agent.connect(req);
3

Send and receive

// Broadcast to everyone in the channel
agent.sendTextMessage('Hello, room!');

// Or address a single agent, with a message type of your own
agent.sendMessage({
  content: 'your turn',
  type:    'game-state',
  to:      'player-2'
});

// Receive
agent.onMessage = (msg) => render(msg.content);

Primitives

Four primitives, one connection

Everything below runs over the same authenticated channel. Pick what you need and ignore the rest.

Channels & messaging

Named, password-protected channels. Broadcast, direct, or filtered delivery, plus ephemeral messages for high-frequency state that shouldn't be persisted.

HTTP long-polling today · WebSocket in development

WebRTC signaling & P2P

Offer/answer and ICE relayed over your channel, with hosted TURN/STUN including TCP-TLS on 443 for strict networks. Data channels for game state, media tracks for calls.

Presence

Know who is in the room. Join and leave events plus a live peer list — the same mechanism every demo on this site uses to show connected players.

Channel storage

A per-channel key-value store (PUT / GET / DELETE / LIST) that survives sessions. BlockParty saves its entire voxel world with it.

JavaScript today · other clients in progress

Browser-safe keys

Mint short-lived, single-use or TTL-bound temporary keys from your server. Your long-lived key never ships inside a client bundle.

Channel scopes

Private scope isolates channels per API key, so two customers can both own "lobby" without ever meeting. Public scope lets any key join the same room — ideal for demos.

How it works

One connection, four capabilities

Your agents talk to named channels through the SDK. The platform handles delivery, ordering and durability; you decide whether a read should come from the live stream or from stored history. WebRTC traffic uses a channel only to introduce two peers — once they are connected, media and data flow directly between them and never pass through the platform.

Read the connection guide

Security model

Keys that are safe to lose

Client-side real-time apps leak credentials by default. The SDK is built so that the thing in the browser isn't worth stealing.

Temporary keys

Your server mints a key with a TTL measured in seconds, optionally single-use, and hands it to the browser. Nothing long-lived ever reaches a client.

Channel isolation

In private scope, the same channel name under a different API key is a different channel. Tenants cannot collide, by construction rather than by convention.

Transport security

TLS on every API call, DTLS on peer-to-peer data channels, and channel passwords hashed in the browser before they are ever sent.
